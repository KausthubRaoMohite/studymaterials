# 90-Day Upskilling Plan (While Working Full-Time)

## Mission

Become interview-ready for backend software engineering roles while
building strong Computer Science fundamentals for technical interviews
and basic GATE-level examinations.

------------------------------------------------------------------------

# Guiding Principle

Do **not** try to study everything every day.

Instead, every study day should contain **three core pillars**:

1.  **Solve** -- Improve problem-solving ability.
2.  **Understand** -- Learn Computer Science fundamentals.
3.  **Build or Explain** -- Apply knowledge through projects or system
    design.

This minimizes context switching and maximizes long-term retention.

------------------------------------------------------------------------

# Daily Structure

## Pillar 1 -- Problem Solving (Daily)

Alternate between **DSA** and **Competitive Programming**.

### Monday

-   DSA

### Tuesday

-   Competitive Programming

### Wednesday

-   DSA

### Thursday

-   Competitive Programming

### Friday

-   DSA

### Saturday

-   Competitive Programming Contest

### Sunday

-   Weak Areas / Problem Review

### Goal

-   Recognize patterns
-   Improve implementation speed
-   Learn debugging
-   Build interview confidence

------------------------------------------------------------------------

## Pillar 2 -- Computer Science (Daily)

Study one subject at a time.

Suggested order:

1.  Discrete Mathematics
2.  Data Structures
3.  Algorithms
4.  Operating Systems
5.  DBMS
6.  Computer Networks
7.  Computer Organization
8.  Theory of Computation
9.  Compiler Design
10. Aptitude
11. Revision

For every topic:

-   Learn the concept
-   Solve previous GATE questions
-   Explain the concept without notes

------------------------------------------------------------------------

## Pillar 3 -- Build or Explain (Daily)

Rotate between:

### System Design

Examples:

-   URL Shortener
-   WhatsApp
-   Instagram Feed
-   Notification Service
-   Payment Gateway
-   Rate Limiter

Focus on:

-   Requirements
-   APIs
-   Database
-   Cache
-   Scaling
-   Trade-offs
-   Failure handling

------------------------------------------------------------------------

### Backend Project

Continuously improve one backend project.

Ideas:

-   Kafka Order Processing
-   URL Shortener
-   Notification Service
-   Restaurant Backend
-   Authentication Service
-   API Gateway
-   Distributed Cache

Every week should produce visible progress.

------------------------------------------------------------------------

### Interview Revision

Practice explaining concepts aloud.

Examples:

-   Why Kafka over RabbitMQ?
-   CAP vs PACELC
-   Redis vs PostgreSQL
-   MVCC
-   ACID
-   Vector Clocks
-   Leader Election
-   Consistent Hashing

If you cannot explain it clearly, revisit it.

# Weekly Review

Every Sunday answer:

-   What did I complete?
-   What mistakes did I repeat?
-   What topic still feels weak?
-   What is next week's objective?

Maintain an error log for:

-   Coding mistakes
-   Conceptual mistakes
-   Interview mistakes

Review it every week.

------------------------------------------------------------------------

# Rules

1.  Solve before watching solutions.
2.  Build something every week.
3.  Revise every day.
4.  Explain concepts aloud.
5.  Keep an error log.
6.  Review mistakes weekly.
7.  Prioritize mastery over completion.

------------------------------------------------------------------------

# Success Criteria After 90 Days

## Problem Solving

-   Comfortable solving medium-level DSA problems
-   Regular competitive programming participation
-   Faster implementation and debugging

## Computer Science

Strong understanding of:

-   Data Structures
-   Algorithms
-   Operating Systems
-   DBMS
-   Computer Networks
-   Discrete Mathematics

## System Design

Able to design common distributed systems and discuss trade-offs
confidently.

## Projects

At least one substantial backend project demonstrating real engineering
concepts.

## Interview Readiness

Able to:

-   Solve coding problems confidently
-   Explain CS fundamentals clearly
-   Discuss architecture and trade-offs
-   Showcase practical project experience

------------------------------------------------------------------------

# Remember

Your goal is **not** to finish courses.

Your goal is to become someone who can:

-   Solve problems
-   Understand systems
-   Build software
-   Explain engineering decisions confidently

Consistency over 90 days beats intensity for 10 days.
